# Ingestion pipeline — v0.2.0

## Change

The initial context design is implemented as a durable asynchronous workflow. Raw sources, database records, vectors, and progress telemetry have separate ownership boundaries.

```mermaid
sequenceDiagram
    participant C as Client
    participant A as API
    participant P as PostgreSQL
    participant O as Object Storage
    participant R as Redis/Dramatiq
    participant W as Worker
    participant V as Qdrant
    participant M as OpenRouter

    C->>A: POST /v1/ingestions + Idempotency-Key
    A->>P: Create job/documents
    A->>O: Persist raw sources
    A->>R: queued event and task
    A-->>C: SSE queued event
    R->>W: Deliver job
    W->>O: Read source
    W->>M: Batch embeddings
    W->>V: Idempotent deterministic upsert
    W->>P: Final document/job state
    W->>R: Progress and terminal event
    R-->>A: Redis Stream replay
    A-->>C: SSE events
```

## Failure behavior

```mermaid
flowchart TD
    ParseOrEmbed[Parse, embed, or index failure] --> MarkFailed[Mark document failed]
    MarkFailed --> Cleanup[Delete any document vectors]
    Cleanup --> Event[Emit failed SSE event]
    Event --> Next{More documents?}
    Next -->|Yes| ParseOrEmbed
    Next -->|No| Finish[Complete job with error count]
```

The worker is idempotent: chunk IDs derive from document ID and index, so retried upserts replace rather than duplicate vectors.
